**Inspections and checks** capture evidence, validations and quality results. Their rules differ by area.

Use them when a check must link to an actual operation, item, receipt or movement.

## Where they appear

| Area | What it validates |
| --- | --- |
| Production | Operation checks required before starting, before finishing, or optional. |
| Catalog | Inspections associated with the item to define what to review. |
| Warehouse | Mandatory or optional receipt inspections. |
| Maintenance | Mandatory or optional actions with results within a work order. |

Not all checks are strictly about quality. Some record operational confirmations, photos, measurements or files explaining how work was done.

## Result types

| Type | When to use it |
| --- | --- |
| Confirmation | The operator must confirm that an action was done. |
| Yes/no | You need an accepted or rejected result. |
| Number | You want to record a measurement. |
| Text | You need a free-form observation. |
| Image | Visual evidence must be retained. |
| File | A document or external test must be attached. |
| Selection (maintenance) | The technician chooses one of the configured answers. |
| Signature (maintenance) | The technician draws their signature on screen; it is retained as an image. |

Configure the type according to the data you need to retain.

## Manufacturing checks

A manufacturing check asks for one or more values, each with its own type. For example, a check per barrel can ask for pH, acidity and salt level, and a packaging check can ask for vacuum pressure, seal and weight. A check without values is a confirmation. If the check asks for a single value and you do not name it, the value takes the name of the check and changes with it when you rename the check.

Each time the check is done, a **record** keeps those values. If the check asks for several records, each one can have a free reference to tell it apart, such as the barrel or sample number.

### How many records it asks for

| Setting | Effect |
| --- | --- |
| Exact number | The check asks for exactly that number of records. No more can be added. |
| Minimum number, allowing more | The check asks for at least that number of records and more can be added, for example one per barrel when you do not know how many there will be. |

In the recipe, the number of records is a formula, like quantities and durations. For example, `ceil(Production order quantity / 500)` asks for one sample every 500 units of the MO. Insert **Production order quantity** from **Order data** in the editor. The formula is calculated when the MO is created. If it is 0, the MO does not include the check. In the MO you can change the number of records of each check.

Records are not created in advance: they appear when someone adds them.

### Partial records

You can save a record with only some of its values and complete it later. For example, you measure the pH of a barrel and add the acidity when you have the result. Saving only changes the values you send: if two people complete different values of the same record, both are kept. A record is complete when it has all its values.

While a check has records, you cannot add or remove values or change their type. You can still change their names and order.

### When it is required

| Requirement | Effect |
| --- | --- |
| Before starting | Blocks starting and finishing while records are missing or partial. You can record it before starting the operation. |
| Before finishing | Blocks finishing while records are missing or partial. |
| Optional | Does not block the operation. Bold still shows what is pending. |

Checks do not depend on progress: you can record units while checks are pending. Once the operation is finished or cancelled, its records can no longer change.

If the operator cannot start or finish, review which required check has missing or partial records.

### Order

The checks of an operation have their own order, separate from the order of the steps. You can change it in the recipe and in the MO. When the MO is created, its checks copy the order of the recipe.

### In work mode

The operator sees the checks of the operation in that order. An icon at the start of each check shows its status:

| Icon | Status |
| --- | --- |
| Green check | Done. |
| Orange circle with ▶ | Pending and required before starting. |
| Orange circle with a flag | Pending and required before finishing. |
| Empty gray circle | Pending and optional. |

A partial check keeps the pending icon. The green check appears when you complete the required records. Hovering over the icon also shows whether it is partial and whether it blocks the operation.

- A check with a single record takes one line: the name followed by its values, without a reference. If the value has the same name as the check, its name is not repeated. When the values do not fit on the line, they continue on the next one. When a value changes, the **Save** button appears; on phones it only shows its icon. If it only asks for a yes/no value, it is saved when the answer is chosen. Photos and files are saved when uploaded. A confirmation is recorded with **Confirm**.
- A check with several records shows, next to its name, the completed records out of the required ones, such as `2/5`, with `+` if more can be added, and the **Add record** button. The list of records appears below.

## Receipt inspections

A receipt can include mandatory or optional inspections. Only mandatory inspections block receiving while pending.

Configuring and creating receipt inspections requires **Receipt quality inspections** in your plan. When this option is disabled, new lines do not generate automatic inspections. Existing inspections remain in history and can be completed or deleted depending on the receipt's status.

After receiving, the receipt and its inspections are protected to preserve history.

## Maintenance actions

Actions in a maintenance work order can be mandatory or optional. Complete all mandatory actions before finishing the work order. Optional actions can remain pending. If you complete an action, its result must match the configured type.

You can also configure a **Selection** action with fixed answers or a **Signature** action for the technician to draw their signature. The signature is stored as an image and retains the **Signature** result type in the work order.

## Relationship with costs and traceability

Checks do not calculate costs on their own, but explain deviations, rejects, rework or blocks.

When an inspection generates a rejection, pause or adjustment, connect the result to [Checks, consumption and pauses](/en/concepts/manufacturing/checks-consumption-and-pauses), [Stock and movements](/en/concepts/warehouse/stock-and-movements) or [Theoretical cost vs actual cost](/en/concepts/costs/planned-versus-actual-cost).
