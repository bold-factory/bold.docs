A user is the account a person uses to access Bold. Invite each person who needs their own access to the application or administrative functions.

<Info>
  A user and an employee are different. The user controls access and permissions. The employee represents an operational person for shifts, work, costs or assignments.
</Info>

## Before inviting

- Be clear about which modules the person must use.
- Create or review the permission profile you will assign.
- Decide whether to link them to an operational employee.
- Avoid sharing one account among several people if you need auditing.

## Invite a person

**Path:** **Control panel > Users > Invite**

Fields to complete:

| Field | What to enter |
| --- | --- |
| **Email** | Email address that will receive the invitation. |
| **Employee** | Operational employee to link to the account. |
| **Role** | Permission profile to apply to the user. |

In **Employee**, choose one of these options:

- **Link to an existing employee:** if the person is already registered as an employee.

- **Create new employee:** if they are not registered yet.

If you link an existing one, select them in **Employee**. If you create a new one, complete **First name**, **Last name** and, where applicable, **Employee code**.

The assigned profile determines the screens and actions the user can access.

## Link a user and employee

Link the user to an employee when their actions should be associated with an operational person. This matters on the shop floor and in shifts, costs, assignments and tasks.

Common cases:

- An employee who records work from a tablet.
- A manager who acts on behalf of an employee in an operational workflow.
- An account that needs to view data but does not record work. In this case, it may not need an employee link.

## Recommendations

| Situation | Recommendation |
| --- | --- |
| New warehouse manager | Assign warehouse read and write permissions. |
| Shop floor operator | Assign production work permissions and an employee link. |
| Planner | Assign planning, purchasing and production read and write permissions according to the process. |
| Technical integration | Use a technical credential managed by an administrator instead of a personal account. |
| Temporary user | Use minimal profiles and set an access review date. |
