Un **artículo** identifica un elemento físico concreto. Es la unidad que Bold usa para controlar stock, compras, ventas, fabricación, consumos, lotes y costes.

## Qué controla

| Área | Uso del artículo |
| --- | --- |
| Catálogo | Nombre, código, unidad, imagen, familia y valores de propiedades. |
| Almacén | stock por ubicación y lote opcional. |
| Compras | Líneas de pedido, proveedor preferente y plazos. |
| Ventas | Líneas de pedido y compromisos de entrega. |
| Fabricación | Artículo fabricado, entradas consumidas y coproductos. |
| Planificación | Origen, modo de aprovisionamiento, punto de pedido y cantidades recomendadas. |
| Costes | Coste base, coste real, lote y valoración de inventario. |

## Identidad del artículo

El código debe ser estable. Cambiarlo cuando ya existe actividad complica búsquedas, integraciones y trazabilidad.

La unidad define cómo se expresan cantidades. Debe ser la unidad con la que el equipo compra, almacena, consume o fabrica ese artículo de forma consistente.

## Artículos con familia

Un artículo puede pertenecer a una familia. En ese caso representa una de sus variantes.

| Familia | Artículo |
| --- | --- |
| Mesa Nórdica | Mesa Nórdica - 160 cm - Roble |
| Mesa Nórdica | Mesa Nórdica - 200 cm - Nogal |
| Envase 500 ml | Envase 500 ml - Transparente |

Si la familia tiene propiedades requeridas, el artículo debe completar sus valores. Mientras falte alguno, la interfaz muestra **Falta información**. Cuando están todos informados, muestra **Todo en orden**.

Dos artículos activos con la misma familia y los mismos valores suelen indicar un duplicado o una propiedad que falta.

## Consolidación de artículos

Bold puede proponer consolidar artículos cuando tienen la misma familia y los mismos valores de propiedades. Consolidar deja un artículo como referencia válida y retira el duplicado, moviendo sus relaciones operativas al artículo que permanece.

Úsalo solo cuando ambos registros representen exactamente el mismo elemento físico. Si dos artículos parecen duplicados pero no lo son, falta una propiedad para explicar la diferencia.

Si consolidaste dos artículos que no eran iguales, crea un nuevo artículo con las propiedades correctas y reasigna manualmente pedidos, recetas o datos operativos según el caso.

## Artículos sin familia

Un artículo puede existir sin familia cuando no necesita agruparse con variantes. En ese caso, su información se considera completa porque no tiene propiedades requeridas por una familia.

Usa esta opción para repuestos, consumibles o referencias únicas que no comparten propiedades con otros artículos. Una receta puede vincularse directamente al artículo aunque no pertenezca a una familia.

## Datos que afectan a planificación

| Campo | Qué decide |
| --- | --- |
| Origen de aprovisionamiento | Si se compra, se fabrica o se ignora en recomendaciones. |
| Modo de aprovisionamiento | Si se cubre contra pedido o contra stock. |
| Punto de pedido | Nivel que dispara reposición contra stock. |
| Pedido mínimo | Cantidad mínima sugerida. |
| Tamaño de lote | Múltiplo usado para redondear recomendaciones. |
| Plazo de aprovisionamiento | Anticipación necesaria para compra o fabricación. |

Estos datos no describen el artículo físicamente. Describen cómo debe reponerse.

Consulta [Política de aprovisionamiento](/es/conceptos/planificacion/politica-de-aprovisionamiento) para ver cómo estos campos afectan a compras, fabricación y recomendaciones.
