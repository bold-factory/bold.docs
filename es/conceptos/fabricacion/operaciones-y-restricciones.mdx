Una **operación** es una etapa ejecutable de una receta u orden de fabricación. Puede tener entradas, pasos, controles, recursos, tiempos y restricciones.

## Qué define una operación

| Dato | Uso |
| --- | --- |
| Proceso | Tipo de trabajo que se ejecuta. Consulta [Procesos](/es/conceptos/fabricacion/procesos). |
| Estación o recurso | Dónde se puede ejecutar. |
| Entradas | Materiales consumidos durante la etapa. |
| Pasos | Instrucciones visibles para el operario. |
| Controles | Comprobaciones obligatorias en el momento configurado. |
| Tiempo previsto | Base para planificación, coste y eficiencia. |
| Cantidad | Progreso que aporta a la orden. |

## Cuándo queda planificada

Una operación pasa a **Planificada** cuando tiene:

- una estación de trabajo;
- una fecha objetivo;
- una herramienta seleccionada, si la operación exige una característica de herramienta.

La disponibilidad de materiales se muestra por separado. No forma parte de estos requisitos mínimos de planificación.

## Restricciones

Las restricciones relacionan una operación anterior con una siguiente. Configura por separado cuándo puede empezar la siguiente y cuántas unidades puede registrar.

| Condición de inicio | Se cumple cuando la anterior… |
| --- | --- |
| En cualquier momento | No impone una condición de inicio. |
| Haya empezado | Ya ha iniciado el trabajo. |
| Tenga unidades buenas o haya finalizado | Tiene alguna unidad buena, o ha finalizado aunque no tenga unidades. |
| Haya finalizado | Ha terminado. |

La condición de inicio deja de aplicarse cuando la operación siguiente empieza. Una operación anterior finalizada o cancelada deja de imponer restricciones.

| Límite de unidades | Mientras la anterior sigue abierta… |
| --- | --- |
| Sin límite | Puedes registrar cualquier cantidad. |
| Según se completan | Las unidades buenas de la anterior liberan unidades en proporción a las cantidades planificadas. |
| Todo el lote al finalizar | No hay unidades disponibles hasta que la anterior finaliza. |

El límite cuenta las unidades buenas y rechazadas que registras en la siguiente. Las rechazadas de la anterior no liberan unidades. Con varias operaciones anteriores, se aplica el límite más bajo.

Por ejemplo, si una operación tiene previstas 10 planchas y la siguiente 40 piezas, una plancha buena libera 4 piezas. Cuando la anterior finaliza, deja de limitar aunque haya completado menos cantidad de la prevista.

### Qué ocurre si no se cumple

| Exigencia | Modo de trabajo | Gestión |
| --- | --- | --- |
| Avisar | Confirma el diálogo de advertencia para continuar. | Confirma el diálogo de advertencia para continuar. |
| Solo deliberadamente | Confirma el diálogo para continuar. | Confirma el diálogo para continuar. |
| El operario no puede | La acción queda deshabilitada. | Puedes confirmar el diálogo si tienes permiso de escritura de órdenes de fabricación. |

**Avisar** muestra un indicador informativo y mantiene la operación visible al activar **Ocultar restringidas**. **Solo deliberadamente** muestra una advertencia y permite ocultarla con ese filtro mientras no haya empezado. Ambos requieren la misma confirmación para continuar; no hay un paso adicional ni se exige una causa.

Bold registra qué restricciones te has saltado y su exigencia en el momento de la acción. El backend también aplica los bloqueos a las llamadas de API que inician o registran unidades en una operación individual. Las [acciones de un grupo](/es/conceptos/fabricacion/asignaciones-y-grupos-de-operaciones) están exentas de estas restricciones, tanto en gestión como en modo de trabajo.

El indicador muestra si puedes continuar, si faltan unidades o si hay condiciones pendientes. En **Información** puedes revisar cada condición y abrir la operación anterior para comprobar si falta registrar progreso.

El filtro **Ocultar restringidas** oculta solo operaciones sin iniciar con condiciones pendientes de tipo **Solo deliberadamente** o **El operario no puede**. Las operaciones que ya empezaron siguen visibles.

### Preparación anticipada y esperas

Para preparar una operación mientras la anterior produce, elige el inicio cuando la anterior haya empezado. Decide si recibes las unidades según se completan o todo el lote al finalizar.

Una espera temporizada no ofrece **En cualquier momento**. El inicio automático respeta todas sus condiciones de inicio, incluso las configuradas como **Avisar**. Si empieza antes de que terminen sus operaciones anteriores, no se completa automáticamente hasta que haya transcurrido su duración y hayan cerrado todas las anteriores.

La secuenciación sigue las condiciones, con independencia de su exigencia. Una precedencia configurada como **Avisar** también puede ordenar el plan.

No deben duplicarse ni crear ciclos. Un ciclo impediría saber qué operación desbloquea a otra y puede bloquear la [secuenciación](/es/conceptos/fabricacion/secuenciacion).

## Operación final

La operación final suele ser la que no tiene restricciones salientes. Bold puede usarla para derivar cantidad completada, rechazada y pendiente de la orden.

Define bien la operación final cuando hay ramas paralelas, coproductos o controles finales.

## Estados de una operación

| Estado | Significado |
| --- | --- |
| **Pendiente de planificar** | Falta planificación o asignación necesaria. |
| **Planificada** | Puede prepararse para ejecución. |
| **En curso** | El trabajo empezó. |
| **Pausada** | La operación está detenida por una interrupción. |
| **Finalizada** | La operación terminó. |
| **Cancelada** | La operación ya no debe ejecutarse. |

Consulta [Estados de fabricación](/es/conceptos/fabricacion/estados-de-fabricacion) para comparar operaciones con órdenes, grupos y planes.

## Deshacer una finalización

Puedes usar **Deshacer finalización** sobre una operación finalizada. Debes indicar un motivo de pausa.

Bold reabre la operación y crea una interrupción desde la fecha en la que se finalizó. Los consumos ya registrados no se eliminan. Revísalos antes de continuar si la finalización anterior generó registros que ya no corresponden.

## Granularidad

| Operaciones demasiado grandes | Operaciones demasiado pequeñas |
| --- | --- |
| Ocultan cuellos de botella. | Obligan a registrar cambios constantes. |
| Dificultan medir avance real. | Cargan al operario con exceso de interacción. |
| Mezclan consumos y controles distintos. | Complican planificación sin aportar trazabilidad. |

Elige el nivel en el que necesitas medir progreso, consumo, calidad o responsabilidad.
